# MrBot1000 v2.0.22 — Plan

## Theme
Security-first hardening for external platform interaction, then platform adapter
primitives. Driven by the operator's standing directive: the app runs on ANY
hardware (6GB Zen3 DDR4 → modern RTX) with ANY Ollama model, and may later switch
to vLLM / add cloud (OpenRouter etc). Model SIZE is NOT a concern and must never be
warned about.

## Decisions (from operator, this session)
- v2.0.21 P1#3 "large chat model" heuristic is DEPRECATED → **removed** (it
  contradicted the hardware-agnostic goal). Keep only "model unset" checks.
- SECURITY POLICY for discovered platform instructions (e.g. remote `SKILL.md`):
  - Any instruction fetched from the web is **UNTRUSTED DATA**, never an agent
    directive. Treating it as a directive = prompt injection.
  - Auto-**quarantine** + **flag for human review**. State = `pending`.
  - On approval → move to **allowlist** (executable / trusted).
  - On rejection → move to **blacklist** (url + skill.md content hash + related
    identifiers). Blacklisted items are ALWAYS ignored (never fetched/executed).
- Build order: **(C) security gate first**, then adapter skeleton + auth/action.

## v2.0.22 Scope

### 1. Instruction Provenance Gate (SECURITY — first)
New module `agents/instruction_gate.py`:
- `fetch_instruction(url, *, kind="skill.md")` — central fetch for ANY external
  instruction/playbook. Pulls content, computes a content hash, checks the
  allowlist/blacklist (managed in `agent.db`), and returns a `QuarantinedInstruction`
  object with `status` (`pending`|`allowed`|`blocked`).
- Blacklist short-circuits fetch (returns `blocked` without network).
- On first sight of an unknown instruction → `pending`, recorded for review,
  content NOT executed/trusted.
- `review_instruction(id, approve: bool)` — moves pending → allowed (allowlist) or
  blocked (blacklist).
- `list_pending()`, `list_allowlist()`, `list_blacklist()` — for the UI/review.

DB tables (database.py):
- `instruction_allowlist(url TEXT PK, content_hash TEXT, title TEXT, approved_at REAL)`
- `instruction_blacklist(url TEXT PK, content_hash TEXT, related TEXT, rejected_at REAL)`
- `instruction_quarantine(id, ts, url, kind, content_hash, content TEXT, status, title)`

### 2. Main-model / high-trust action boundary
- Define which actions are "high-trust" (account creation, password set, post/cross-
  post, sending funds, downloading+executing files). These MUST run on the main model
  with an explicit human-confirmation gate; discovered instructions can NEVER trigger
  them automatically. (Scaffolding + the confirmation hook; full enforcement matures
  with the adapter layer.)
- AI-policy tag on discovered platforms: `ai_allowed` / `ai_disallowed` (some sites
  forbid AI). Gate respects this — if `ai_disallowed`, only human-in-the-loop actions.

### 3. Platform Adapter skeleton (after security)
- `agents/platforms/base.py`: `PlatformAdapter` ABC with primitives:
  `authenticate()`, `fetch_instructions()` (routes through gate), `list_actions()`,
  `execute_action(action, *, confirmed_by_human=False)`.
- Concrete no-op stubs for Fiverr/Upwork/Reddit/LinkedIn/Discord/airdrop to show the
  shape; wire `fetch_instructions` through `instruction_gate`.
- Auth primitives: credential store reference (NEVER plaintext in code; read from a
  secrets backend / .env at runtime, never committed).

### 4. UI review surface (minimal, ties to DB Stats / a new "Review" panel)
- Show pending instructions with Approve/Reject buttons (the human-in-the-loop).
- Show allowlist/blacklist counts.

### 5. Housekeeping
- Remove P1#3 large-model warning.
